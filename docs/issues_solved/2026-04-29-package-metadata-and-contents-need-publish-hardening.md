# Publishable Crates Need Metadata And Package Boundaries
Status: solved
Found while: deep library-readiness and legacy-residue review
Scope: Cargo.toml, crates/ink-compiler/Cargo.toml, crates/ink-runtime/Cargo.toml, crates/ink-story-json-format/Cargo.toml
Problem: The facade and library crates are shaped for downstream use, but their manifests lack core package metadata, and the root facade package has no `include` boundary. `cargo package -p ink-rs --list` packages repository process files, plans, issue records, editor assets, and the upstream writing-guide snapshot.
Why it matters: Publishing or consuming the crates from a registry will produce warnings, weak crate discovery, and an unnecessarily large root crate package with internal project material that game projects do not need.
Suggested fix: Publish the root `ink-rs` facade plus `ink-runtime`, `ink-compiler`, and `ink-story-json-format`; keep `ink-test` and `ink-tools` as `publish = false`. Add package metadata, package-specific descriptions, and a root `include` list that keeps only the facade source and intended user-facing docs. Repository URL can come from git remote if present; license still needs an explicit owner/project choice before publishing.
Evidence: `Cargo.toml:1` has only a root package description and no license/repository/readme/include. `crates/ink-compiler/Cargo.toml:1`, `crates/ink-runtime/Cargo.toml:1`, and `crates/ink-story-json-format/Cargo.toml:1` lack descriptions and metadata. `cargo package -p ink-rs --list` warned `manifest has no license, license-file, documentation, homepage or repository` and listed `AGENTS.md`, `Notes.md`, `docs/finished_plans/*`, `docs/issues_*/*`, and `editor/vscode-ink-rs/*`.
Owner decision: Use the facade-plus-three-library-crates publish strategy; internal test/tool crates remain unpublished.
Resolution: Added repository, documentation, keywords, descriptions, and package include boundaries for the facade and three publishable library crates. Added a root `README.md` for downstream dependency and API discovery. The root package now includes only the facade source and intended user-facing docs instead of internal plans, issue records, editor assets, or the upstream guide snapshot.
Remaining publishing decisions: License metadata is still intentionally unset because it requires an owner/project legal choice. First publication must publish `ink-story-json-format` before `ink-compiler` and `ink-runtime`, then publish `ink-rs`, because Cargo validates packaged registry dependencies against crates.io.
Validation: `cargo package -p ink-rs --list --allow-dirty`; `cargo package -p ink-runtime --list --allow-dirty`; `cargo package -p ink-compiler --list --allow-dirty`; `cargo package -p ink-story-json-format --list --allow-dirty`; `cargo package -p ink-story-json-format --allow-dirty --no-verify`; `cargo metadata --no-deps --format-version 1`; `cargo check --workspace`; `cargo check -p ink-rs --features full`; `cargo test -p ink-rs --features full`; `make gate TIMEOUT='f(){ shift; "$$@"; }; f'`.
